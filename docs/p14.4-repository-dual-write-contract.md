# P14.4 — Repository dual-write contract lock

**Date:** 2026-08-25  
**Scope:** Characterize and lock the **current** JSON + PostgreSQL dual-write behavior with tests and this document. **No production logic change. No PostgreSQL-primary cutover. No migrations.**

Tests live in `tests/p14.4-repository-dual-write.test.ts` (behavioral, with test-only `pg.Pool.prototype.query` + `fs.promises` mocks). Source-order assertions in the same file prevent silent reorder.

---

## Current repository architecture

```text
backend/src/http/*     →  server/services/*  →  server/repositories/*
                                                      ├─ json-store  (data/ or /tmp on Vercel)
                                                      └─ queryPostgres (pg Pool, DATABASE_URL)

queryPostgres never throws to repositories: driver errors become null + 30s downUntil.
writeJsonFile never throws to repositories: fs errors are swallowed; in-memory Map is still updated.
There is no BEGIN/COMMIT spanning JSON and PostgreSQL.
```

Handlers and Next BFF do not import repositories. Demo repository does not import PostgreSQL.

## Read behavior

- **merchants:** PostgreSQL rows hide the JSON array when `fromPg.length > 0`.
- **workspaces `loadWorkspace`:** PostgreSQL wins only when `payload.files` is present.
- **workspaces `listWorkspaces`:** if PG returns **any** rows, JSON is **not** consulted (even if every payload lacks `files` after filter).
- **events:** PostgreSQL rows hide JSON; empty PG does **not** hide JSON. `appendEvent` caps JSON at 2000 by `unshift` then `slice(0, MAX)` — it does **not** sort by `at`.
- **guard `listGuardDecisions`:** a successful empty PG result (`{ rows: [] }`) is truthy → `backend: "postgres"` and **hides** the file log.
- **demo:** JSON map + `DEFAULT_NAC_DEMO`.

---

## Write behavior

Do **not** unify these orders:

1. merchants: `writeAccountPg` → `writeJsonFile`
2. workspaces: `writeJsonFile` → `queryPostgres` INSERT
3. events: `writeJsonFile` → `queryPostgres` INSERT with `randomUUID()`
4. guard: `queryPostgres` INSERT → return; else unshift JSON file
5. demo: `writeJsonFile` only

`mergeEvents` writes JSON only and is unused by production HTTP.

---

## Failure behavior

| Layer | Actual |
| --- | --- |
| `queryPostgres` driver throw | Caught inside `server/db/postgres.ts`; returns `null`; `downUntil = now + 30s` (all later queries skip PG) |
| Repositories | See `null`, not the driver error |
| `writeJsonFile` fs throw | Caught; memory Map already updated; repositories proceed |
| Users/workspace/events + `DATABASE_URL` set + `VERCEL` + PG `null` | Throw after the JSON write has already happened |
| Guard + PG `null` | JSON fallback, no Vercel throw |
| JSON read miss | `readJsonFile` returns the provided fallback; does not throw |

---

## Backfill behavior

| When | Who |
| --- | --- |
| PG connected, zero merchant rows, JSON has accounts | `readAccounts` INSERT each JSON account; a later read sees PG rows and does **not** backfill again |
| PG connected (`fromPg !== undefined`, including `null` payload), JSON workspace has `files` | `loadWorkspace` → `saveWorkspace` |
| PG unavailable (`queryPostgres` null / `fromPg === undefined`) | **no** backfill |
| Events | **no** backfill |
| Guard / demo | **no** backfill |

Partial failure: a merchant backfill loop can INSERT some accounts then fail later; **not transactional**.

---

## Ordering differences

Documented in the matrix. P14.4 tests fail if the source order is swapped.

---

## Known non-transactional behavior

JSON success + PG failure (or the reverse for merchants) can diverge. Guard freeze on the account (`upsertAccount` in `server/smart-guard/run.ts`) is a **separate** call from `appendGuardDecision`. No shared transaction.

---

## Concurrency behavior

All JSON collections are read-modify-write without a lock. **Last-write-wins.** Phone uniqueness is `findAccountByPhone` (first match) in the repository; `auth.service` enforces 409 on register, which is a TOCTOU race, not a DB unique.

---

## Data integrity behavior

- `StoredAccount.password` / `resetCodeHash` live in JSONB `payload`. `publicAccount` strips them.
- Workspace `payload` stores files, taxonomy, action log, and serialized transactions.
- `TrackEvent` has **no `id`**; PostgreSQL `id` is generated at insert and is not in the JSON payload.
- Guard `traces` round-trip as JSONB (object or JSON string in `mapPgRow`).
- Freeze log: `frozenAt = verdict.at` when decision is `freeze`, else `null`. Account `guardFrozen*` is a merchant payload field, not a FK.

---

## DO NOT ASSUME

- Do not assume write order is the same across repositories.
- Do not assume PostgreSQL is primary (except guard **write** is PG-first today).
- Do not assume `queryPostgres` throwing is visible to repositories.
- Do not assume `writeJsonFile` throwing is visible to repositories.
- Do not assume events are de-duplicated (`ON CONFLICT` is on random UUID, not the event identity).
- Do not assume empty PG keeps JSON visible (`listGuardDecisions` and `listWorkspaces` can hide JSON).
- Do not assume backfill for events.
- Do not assume phone unique in PostgreSQL.
- Do not assume Vercel throw for guard-log.
- Do not assume `mergeEvents` writes PostgreSQL.
- Do not assume this phase created `database/` or migrations.

P14.4 **locks** this behavior. Changing it needs a later, approved phase — not a silent edit.
