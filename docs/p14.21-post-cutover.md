# P14.21 — Post-cutover verification

**Date:** 2026-08-28  
**Scope:** After P14.20 the write-freeze is lifted and PostgreSQL is the official catalog store. This slice proves **live, controlled** round-trips for merchants, workspaces, track events, and guard decisions, then removes the probe. It **does not delete the archive**, does not change schema, and does not start P14.22.

## Event identity after cutover

| Kind | `track_events.id` | Who writes it |
| --- | --- | --- |
| Backfilled / historical rows | SHA-256 hex (`eventDeterministicId`, 64 chars, no hyphens) | P14.9–P14.11 copier only |
| New `appendEvent` rows | `randomUUID()` (36-char UUID) | production repository |

The JSON payload still has no `id`. Existing SHA-256 keys are **not** migrated. A new event’s UUID is not equal to `eventDeterministicId(payload)`.

---

## What ran

`npm run db:verify-post-cutover`:

- Refuses if the freeze was re-engaged or the P14.20 marker is invalid.
- Does **not** call `db:unfreeze`, `db:backfill`, `db:reconcile`, or `db:migrate`.
- Writes probe `p14.21-verify-probe@store.test` through production repositories.
- Reads each row back from PostgreSQL and matches it.
- Checks the new event primary key is a UUID, not SHA-256.
- Deletes **only** that probe email, and only after read-back succeeds.
- Confirms `data/` catalog JSON is still absent and `nac-demo.json` is unchanged.
- Leaves `.p14.17-json-archive/` in place.

Isolated tests use a mocked `pg.Pool` and `SMARTPROFIT_TEST_PG=1` with a fake URL so they cannot touch live catalogs.
