## Command

Explicit / operator-only (not request-path):

```bash
npm run db:backfill
```

Requires `DATABASE_URL` and `001_current_schema.sql` already applied (`npm run db:migrate`). Aborts with no product INSERT if PostgreSQL is down, `schema_migrations` is missing, 001 is not applied, or the JSON dry-run reports conflicts/rejected rows.

Each group runs in its own `BEGIN` … `COMMIT`. Failure → `ROLLBACK` for that group only.

`ON CONFLICT DO NOTHING` on every INSERT. Demo JSON is skipped.

Event ids: `sha256_hex(NUL-join("smartprofit.track_event.v1", at, type, label, email))`. **No `randomUUID()` in the copier.**

JSON files are read-only.

## Remaining risks

1. **Durable Postgres.** This machine still has no Docker. The verified copy ran on a session cluster. After `npm run db:up` on a new volume, run `db:migrate` then `npm run db:backfill` again (idempotent).
2. **New events vs backfilled events.** Dual-write still mints UUID ids for *new* `appendEvent` rows. Backfilled rows use sha256. Harmless until cutover; P14.11+ should align `appendEvent` with the locked identity.
3. JSON will keep growing; a later copy only inserts new keys (`DO NOTHING`).
4. Orphan workspaces/guards and password-less merchants were copied as-is.
