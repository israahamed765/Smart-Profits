## Track events — identity A proven, not implemented

**D remains rejected:** `randomUUID()` per JSON row during copy.

Production today:

```text
appendEvent → JSON (no id) → INSERT (randomUUID(), at, payload)
ON CONFLICT (id) DO NOTHING   // never matches a second random UUID
```

P14.10 must change `appendEvent` to the **same** function as the copier **in the same slice**. Copying with hashes while inserts still mint UUIDs is acceptable only for *new* events; it is not a substitute for A.

### Algorithm (design lock)

```text
material = join NUL
  "smartprofit.track_event.v1"
  String(at)
  String(type)
  label ?? ""
  normalizeEmail(email ?? "")

id = sha256_hex(utf8(material))
```

NUL separators are required: a pipe-joined key can collide when `label` or `email` contains `|`. This snapshot has **0** labels with `|`, but the copier must not rely on that.

### Proof on this snapshot

| Check | Result |
| --- | --- |
| events | 113 |
| missing `at` / `type` | 0 |
| unknown `type` | 0 |
| JSON `id` present | 0 |
| `mergeEvents` pipe-key collisions | **0** |
| sha256 collisions | **0** |
| missing `label` | 111 |
| missing `email` | 94 |
| `\|` inside `label` | 0 |

Empty `label` / `email` are empty-string slots, same as `mergeEvents`. Uniqueness today is carried by `at` plus `type`; the four-field material is still the identity because that is what the codebase already treats as “the same event”.
