# P14.2 — Frontend cache contract lock

**Date:** 2026-08-25  
**Scope:** Freeze the relationship between Frontend `localStorage` and the Server as a **cache contract**. **No production behavior change.** Auth cookies, APIs, Financial Engine, Smart Guard, and JSON + PostgreSQL dual-write stay as implemented after P14.1.

There is **no** `sessionStorage` usage in the TypeScript tree today.

---

## Frontend Cache Contract

```text
Browser
  localStorage  = cache / UI preference / optional admin display overlay
  cookies       = httpOnly session (sp_session, sp_admin) — not readable as JS auth

Frontend
  AuthProvider / AdminAuthProvider  → GET /api/auth/me, GET /api/admin/me
  AnalysisProvider                  → local workspace cache, then GET/POST /api/workspace
  AppearanceProvider                → theme + locale only
  AdminPortalProvider               → merge local facts with GET /api/admin/snapshot

Server
  requireMerchant / requireAdmin    = ownership and authorization
  repositories                      = durable store (JSON + PostgreSQL)
```

`localStorage` is **not** a Source of Truth, **not** an Authorization source, and **not** a database.

---

## Source of Truth

| Concern | Source of truth | Browser cache |
| --- | --- | --- |
| Merchant identity | httpOnly cookie `sp_session` via `GET /api/auth/me` | none |
| Admin identity | httpOnly cookie `sp_admin` via `GET /api/admin/me` (+ middleware on `/api/admin/*`) | none |
| Workspace ownership | `requireMerchant` → `session.email` on `GET/POST /api/workspace` | slot keyed by that same email |
| Workspace payload | Server JSON + PostgreSQL (P14.1 dual-write) | `smartprofit-workspace-v2:{email}` |
| Taxonomy | embedded in workspace payload on the server | extra slot `smartprofit-taxonomy:{email}` plus copy inside workspace |
| Track events | `POST /api/track` → event repository | `smartprofit-platform-events` (last 400) |
| Admin users/plans | `GET /api/admin/snapshot`, `POST /api/admin/users` | `smartprofit-users` overlay |
| Theme / locale | none (device preference) | `smartprofit-theme`, `smartprofit-locale` |

Reload or login does **not** grant a session from `localStorage`. `AuthProvider` always calls `/api/auth/me`. `AdminAuthProvider` always calls `/api/admin/me`. Guards (`AuthGuard`, `AdminGuard`) read React context filled by those APIs.

`apiFetch` always sends `credentials: "include"`.

## localStorage allowed uses

Documented files (enforced by `describe("P14.2 frontend cache contract")`):

| File | Keys | Kind | Why it is stored locally |
| --- | --- | --- | --- |
| `app/layout.tsx` (inline boot script) | `smartprofit-theme`, `smartprofit-locale` | UI preference | Avoid theme/dir flash before React hydrates |
| `frontend/context/appearance.tsx` | same | UI preference | Persist theme and language on the device |
| `frontend/context/analysis-context.tsx` | `smartprofit-workspace-v2:{email}`, legacy keys, migration flag | Workspace **cache** | Instant restore; quota fallback if POST fails |
| `frontend/lib/tenant.ts` | helpers + `readAllLocalWorkspaces()` | Cache helpers | Keying, legacy migration, admin local overlay |
| `frontend/lib/taxonomy.ts` | `smartprofit-taxonomy:{email}` | Cache | Learned classification terms for the signed-in email |
| `frontend/lib/admin/track.ts` | `smartprofit-platform-events` | Cache | Keep a local event ring while also POSTing `/api/track` |
| `frontend/lib/admin/metrics.ts` | `smartprofit-users`, events, local workspaces | Admin **display overlay** | Merge with server snapshot for the admin UI on this browser |

Workspace in `localStorage` is **Cache / UI state**, not ownership.

## localStorage forbidden uses

Must not (and currently does not) determine:

- merchant identity
- admin authorization
- permissions / plan enforcement on the server
- workspace ownership (server key is `session.email`, not a client-chosen owner)
- Financial Engine results
- Smart Guard / NAC / Step-Up decisions

`frontend/lib/tenant.ts` still **exports unused leftovers**:

- `SESSION_KEY = "smartprofit-session"`
- `SESSION_USER_KEY = "smartprofit-user"`

Nothing calls `localStorage.getItem` on those keys. They are **not** the live session. Live cookies remain `sp_session` / `sp_admin`. P14.2 does not delete the leftovers.

Frontend must not import `server/db`, repositories, or `pg` to implement cache.

## Workspace synchronization model

**Identity first.** `AnalysisProvider` waits for `useAuth()`. `ownerEmail` is `normalizeEmail(user.email)` or `null`. Logged-out users get an in-memory demo file only (not written as a merchant workspace).

**Hydrate (current, locked):**

1. If `ownerEmail` is set, `readLocalWorkspace(ownerEmail)` (dedicated v2 key, else one-time legacy v2/v1 migration into that key).
2. **If local cache is empty**, `GET /api/workspace` (cookie session).
3. If a payload with files exists, restore it; taxonomy is `{ ...readTaxonomy(email), ...workspace.taxonomy }`.
4. Otherwise seed demo settings using `user.storeName` / `user.fullName` from the session API.

This is **cache-first**. A non-empty local slot can hide a newer server copy until a later POST. P14.2 records this; it does **not** change it.

**Persist (current, locked):**

1. `persistLocal(email, workspace)` immediately.
2. `writeTaxonomy(email, taxonomy)`.
3. Debounced 700ms `POST /api/workspace` with `{ workspace }`.
4. Server: `requireMerchant` → `saveMerchantWorkspace(session.email, body.workspace)` (ownership = session, not the JSON `ownerEmail` field alone).

If local quota throws, the comment in code is: server backup still runs.

## Auth / Authorization boundary

```text
localStorage  ✗  cannot log a merchant in
localStorage  ✗  cannot log an admin in
localStorage  ✗  cannot pick which merchant's server workspace to load
cookie + API  ✓  identity
session.email ✓  workspace row key
```

`AuthGuard` redirects to `/login` when `/api/auth/me` has no user.  
`AdminGuard` redirects to `/admin/login` when `/api/admin/me` has no admin.  
`middleware.ts` still checks `readAdminSession` on `/api/admin/*` (except login).

## Admin metrics caveat

`AdminPortalProvider`:

1. Reads `collectClientFacts()` from **this browser's** `localStorage` (users overlay, events, all `smartprofit-workspace-v2:*` slots).
2. Fetches `GET /api/admin/snapshot`.
3. `mergeFacts(local, serverFacts)` — local rows can overlay server rows for **display**.
4. If the snapshot request fails, the UI falls back to `buildAdminSnapshot` from local facts only.
5. `patchUser` writes `smartprofit-users` **and** `POST /api/admin/users`.

This overlay does **not** grant admin login. It **can** make admin charts on that device include cache the server does not treat as authorization. Server plan/status changes still go through the admin API + admin session.

`server/services/admin.service.ts` does not import the localStorage metrics module.

## Cache invalidation / reload behavior (current)

| Event | What happens |
| --- | --- |
| Full page reload | Theme/locale boot from localStorage. Merchant/admin identity from cookies via `/me`. Workspace: local slot if present, else GET `/api/workspace`. |
| Login | Session cookie set by API. `user` from login JSON. Workspace effect re-runs for the new `ownerEmail`. |
| Logout | React user cleared; `POST /api/auth/logout`. Local workspace **keys are not wiped**. They remain cache for that email on this device. |
| Switch account on same browser | Each email has its own workspace key. Cache-first means that account's local slot wins over GET if it exists. |

No automatic invalidation of local workspace after logout. Documented, not changed.

## Known limitations

1. **Cache-first hydrate** can serve stale workspace vs PostgreSQL/JSON.
2. **Non-transactional** server dual-write (P14.1) plus a separate browser cache — three copies can diverge.
3. **Admin display merge** can mix this device's cache into the admin snapshot UI.
4. **Taxonomy dual slots** (workspace JSON + `smartprofit-taxonomy:{email}`).
5. **Unused `SESSION_KEY` / `SESSION_USER_KEY` / `readJson` / `writeJson` helpers** in `frontend/lib/tenant.ts` — leftovers, not live auth.
6. **Logout does not clear** workspace/taxonomy/events keys.
7. Unused backend re-exports from P14.1 remain unused; P14.2 does not touch them.

## Correct vs incorrect usage

**Correct (current):**

```text
GET /api/auth/me  →  user.email  →  workspaceKey(email) cache
POST /api/workspace with cookie  →  save under session.email
theme in localStorage  →  CSS class only
```

**Incorrect (forbidden; not how production auth works):**

```text
localStorage["smartprofit-session"]  →  treat as logged in
pick ownerEmail from a workspace blob without a session
admin login from smartprofit-users
frontend import of server/repositories to "warm" cache
```

## What P14.2 is not

- Not a rewrite of hydrate order (local vs server)
- Not clearing cache on logout
- Not making PostgreSQL primary
- Not changing APIs, cookies, CSRF, CORS, Guard, NAC, Step-Up, or the Financial Engine
- Not deleting stubs or `lib/utils.ts`
- Not P14.3

This behavior is **locked**. Changing cache-first hydrate, admin fact merge, or leftover keys needs a later approved phase.
