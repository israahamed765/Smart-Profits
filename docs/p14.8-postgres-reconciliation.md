## 6. Track events — identity decision (A)

JSON: **109** events, **0** with `id`. PostgreSQL: **0** rows. Natural-key collisions: **0** (`109 / 109` unique `at|type|label|email`).

| Field | Missing on this snapshot |

| `type` | 0 |

`at` is unique for all 109 rows today, so uniqueness currently rides on the timestamp. Empty `label` / `email` still participate as empty-string slots in the key (same as `mergeEvents`).

### Official strategy: **A** (deterministic identity)

**D is rejected** and must not be used in P14.9/P14.10: minting a fresh `randomUUID()` per JSON row during backfill would not match a later dual-write of the same payload.

Concept only — **not implemented in P14.8**:

```text
eventKey = at | type | (label ?? "") | (email ?? "")
id       = deterministic hash / UUIDv5 of eventKey

JSON backfill  → same id
future append  → same id
ON CONFLICT    → no duplicate
```

Production `appendEvent` still inserts `[randomUUID(), event.at, JSON.stringify(event)]`. Changing that is a later slice, together with the backfill writer. P14.8 does not touch `event.repository.ts`.

Option B (stamp JSON with UUID) is not chosen. Option C (defer events) is a possible **scope** split inside P14.9, not a competing identity.
