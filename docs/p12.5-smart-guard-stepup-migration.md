## Session / cookie boundary

- Identity comes from the merchant session (`sp_session`), not from `body.email`, when a session exists.
- Step-Up after login uses `session.email`. A victim address in the body cannot switch the challenge.
- Pre-login `login` / `password_reset` may still use `body.email` (unchanged).
- Cookie flags unchanged: `sp_session` / `sp_admin`, httpOnly, SameSite=Lax, host-only (no `Domain`), Secure in production. No `SameSite=None`.
- CORS merge still copies `Set-Cookie` via `getSetCookie()` so credentials are not dropped.

---

## CORS / CSRF

Unchanged from P12.2–P12.4:

- Allowlist = `FRONTEND_ORIGIN` / `APP_URL`. Never `Access-Control-Allow-Origin: *`.
- `credentials=true` only with an exact allowed origin.
- POST without Origin, or from a foreign origin → `403` (`assertSameOrigin`).
- GET/HEAD/OPTIONS skip CSRF. Logs GET without Origin is `401` if anonymous, not `403`.

## Step-Up flow

1. `POST /send` → server-only challenge (SHA-256 hash in memory). `demoCode` only in simulator (`NAC_API_KEY` empty).
2. Correct 6-digit code → consumed once → `verifyNetworkChallenge` deletes the row → `runSmartGuard`.
3. Replay → `403` (`missing`). Wrong code → `403` (`mismatch`). Rate limits unchanged (send 5/60s, verify 10/60s).
4. OTP / `SESSION_SECRET` / `NAC_API_KEY` never go through `NEXT_PUBLIC_*` or the Client bundle as values.

---

## Fail-Closed flow

`POST /evaluate` resolves identity **first** (unknown action → `400`, not Allow). Then:

```
try evaluateSensitiveAction → 200 { verdict }
catch → 503 { verdict: freeze / check_failed }
```

Not a generic `500` from `backendApiRoute`. Policy in `lib/smart-guard/policy.ts` is unchanged (one brain). Recent SIM swap still Freeze. Missing/unknown action is `400`.

## Copied Guard logic?

**No.** `backend/src/services/guard.ts` re-exports `server/services/guard.service`. Handlers call that service (plus existing `identity` / `requestMeta` / rate-limit — same as the old Next routes). `guardApi` is a live function bag of the same `evaluateSensitiveAction` reference so tests can force a dependency throw; it is not a second policy engine.

`requestMeta` was lifted to `server/http/request-meta.ts` so the backend does not import `next/server` via `server/http.ts`.

## Remaining risks

- OTP challenges live in an in-memory `Map` (unchanged). Next BFF and a standalone backend process do **not** share that map. Prefer one process (empty public API base, or always proxy via `BACKEND_URL`).
- Host-only cookies: `localhost:3000` ↔ `localhost:4000` can share; `127.0.0.1:4000` cannot.
- `/api/nac/*` still on Next (P12.6).
- A stale backend on `:4000` will 404 Guard until it is restarted with this code.
