## What this slice does

```text

```

Does **not** run `db:backfill`. Product repositories and API contracts are unchanged.

---

## Rules

| Allowed | Forbidden |
| --- | --- |
| Record every conflict | Automatic DELETE |
| `UPDATE workspaces` **only** when `savedAt` is trusted ISO-8601 and strictly newer | Blind `UPDATE` of a differing workspace |
| `INSERT … ON CONFLICT DO NOTHING` for valid JSON-only Guard IDs | Treating PG-only rows as errors or deleting them |
| Document PG-only Guard IDs with `retain_in_postgres_not_in_json_snapshot` | Copying those IDs into JSON without an explicit later cutover decision |
| Classify SHA-256 vs UUID event rows; fail on duplicate payloads | Rewriting UUID event ids or changing `appendEvent` |
| Stop when a timestamp is missing / equal / non-ISO | Assuming JSON or PG is correct just because it exists |

Trusted timestamp: `YYYY-MM-DDTHH:mm:ss.sssZ` (or without millis) that `Date.parse` accepts. Equal timestamps with different payloads stay **unresolved**.

---

## Guard union

```text
Union(JSON ids, PG ids)
  → each id once
  → JSON-only valid UUIDs inserted into PG
  → PG-only retained in PG, not copied to JSON, not deleted
```

The PG-only set is a **documented leftover**, not a silent extra. JSON stays the product source of truth until a later cutover decides whether those rows belong in JSON.

---

## Event identity

Locked hash (P14.9 / P14.10). Dual-write still uses `randomUUID()`:

```text
sha256(NUL-join("smartprofit.track_event.v1", at, type, label, email))
```

UUID rows whose **payload** hashes to a JSON event are the dual-write identity of that event, not a duplicate. Duplicate payload hashes in PG are conflicts. Unmatched UUID payloads are conflicts. Ids are not rewritten.
