# P13.5 — Final architecture audit

**Date:** 2026-08-25  
**Scope:** Canonical import audit + boundary confirmation after P13.4. No folder moves. No second Next app. No P14.

---

## Architecture snapshot

```text
app/          Next routing, UI pages, BFF (`app/api/*` → backend handlers)
frontend/     components, context, API client, i18n, UI helpers
backend/      HTTP adapters (node:http)
server/       services, repositories, crypto, CSRF, parser, Guard/NAC I/O
shared/       types, contracts, Zod, math, identity, phone
lib/          dual-use kernels + compatibility barrels + empty landmine stubs
public/ tests/ docs/
```

No `frontend/app/`. No `frontend/package.json`. `app/` remains at the repo root.

**Dependency direction (enforced):**

```text
app UI   → frontend → shared  (+ documented dual-use kernels)
app BFF  → backend  → server  → shared
```

Forbidden: `frontend → backend|server|db|secrets`, `shared → frontend|backend|server`, `backend → frontend`.

## Canonical import rules

| Kind | Canonical path |
| --- | --- |
| UI components / context | `@/frontend/components/*`, `@/frontend/context/*` |
| Frontend-only libs | `@/frontend/lib/*`, `@/frontend/ui/cn` |
| Dual-use kernels | `@/lib/financial-engine/core/*`, `@/lib/smart-guard/policy`, `@/lib/smart-guard/types`, `@/lib/admin/config`, `@/lib/admin/types`, formula barrels (`@/lib/analytics`, …) |
| Shared contracts | `@/shared/*` |
| BFF | `@/backend/src/http/*`, `@/server/http/proxy-to-backend` |

**P13.5 rewrite:** 64 files under `frontend/` and `app/` (UI only) changed from `@/components/` / `@/context/` to `@/frontend/...`. No new shims. `tsconfig` still maps `@/components/*` and `@/context/*` as a non-canonical compatibility alias; architecture tests forbid using those paths in UI source.

Retired P13.2 shim paths (`@/lib/format`, `@/lib/api/client`, …) remain unused and **deleted** (P13.3). They were not recreated.

---

## Frontend boundary

**PASS.** `frontend/**` does not import `backend/`, `server/`, `pg`, parser packages, `node:*`, SMTP, or secret env names.

Allowed: `frontend/**`, `shared/**`, dual-use kernels, browser APIs, `@/frontend/lib/api/client`.

UI pages in `app/` (non-`api`) import `@/frontend/*` only for UI. `app/api/*` is BFF and may import `backend` + `server/http/proxy-to-backend` (not Frontend).

---

## Backend boundary

**PASS.** `backend/**` does not import `@/frontend`, `@/components`, `@/context`, or React.

Flow remains HTTP → Handler → `server/services` → repository → database. Handlers were not thickened in this wave.

## Remaining risks

1. `lib/` still mixes kernels, barrels, and empty stubs — readable but historically dense.
2. `lib/utils.ts` and some `lib/shared/*` aliases are unused; deletion is a later, explicit cleanup (not P13.5 / not P14 here).
3. No `database/` migrations folder; schema is still created at runtime behind repositories.
4. Compatibility path aliases `@/components` / `@/context` still resolve; they must not be used in new UI code.
5. Turbopack traces `server/storage/json-store.ts` (pre-existing warning). Unrelated to this wave.
