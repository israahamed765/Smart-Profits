Does **not** INSERT/UPDATE/DELETE catalogs. Does **not** run `db:reconcile`, `db:backfill`, or `db:cutover`. ## What this proves

| Check | Pass means |
| --- | --- |
| PostgreSQL reachable | Pool SELECT succeeds; repositories would not take the JSON branch |
| PG-primary reads | Merchant / workspace / event / guard SELECTs used by repositories succeed |
| JSON fallback not required | Every JSON catalog row is already in PostgreSQL (`missing` / `json-only` = 0) |
| 10 PG-only guards | Documented leftovers only; not copied into JSON; unexpected PG-only = 0 |
| JSON catalogs on disk | Shadow still present; this slice does not delete |
| `nac-demo.json` | Out of cutover; not a PostgreSQL table; not deleted |
| Freeze | Remains engaged |

The 10 documented Guard PG-only rows exist **only** in PostgreSQL. Falling back to JSON would omit them. That is why production reads stay PostgreSQL-primary.
