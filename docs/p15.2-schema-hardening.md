## What changed

### Merchants

`findAccount` and `upsertAccount` use `SELECT payload FROM merchants WHERE email = $1`.  
`findAccountByPhone` filters in SQL (`payload->>'phone'`).  
`readAccounts` still lists the full table for admin.  
Merge is still in-process on **one** row (residual last-write-wins without `FOR UPDATE`).

### Events

`readEventsPage` keyset: `ORDER BY at DESC, id DESC` plus `WHERE (at, id) < ($2, $3)`.  
`readEvents()` still returns the latest page up to 2000 (compatible callers).  
`readEventsAll()` walks pages (admin snapshot).  
`appendEvent` still inserts `randomUUID()`. Historical SHA-256 ids untouched.

### Pool

`statement_timeout = 8000` ms on the pool.  
Connectivity errors (`ECONNREFUSED`, `ETIMEDOUT`, `ENOTFOUND`, `ECONNRESET`, `EPIPE`, `0800x`, `57P0x`) back off **5s** (`PG_CONNECT_BACKOFF_MS`).  
Query/statement errors — including `statement_timeout` (`57014`) — fail that request only. They do **not** set `downUntil` and do **not** poison catalog reads for 30s.  
No retry loop (a retry would double wall time under timeout and hang mocked tests).

### Orphans

Classified, not deleted. See live run above.

### Guard `created_at DESC` index

Evaluated, **not created**. Unfiltered admin listing is Seq Scan + Sort at current cardinality. `guard_decisions_email_created_idx` already covers the merchant path. Adding an index needs a migration → P15.3 after GO.

## Residual risks (do not fix in P15.2)

- Merchant merge is still last-write-wins without `FOR UPDATE` / a transaction.
- Workspace save is still last-write-wins JSONB (out of scope).
- Unfiltered guard listing is still Seq Scan + Sort; index deferred to P15.3.
- `readAccounts` / `listWorkspaces` still full scans (admin).
- Phone lookup has no expression index.
- Connectivity backoff is 5s, not zero; query errors fail that request only.
- Admin snapshot walks all event pages up to 10_000 (was a silent 2000 cap). Same `AdminFacts` shape.
