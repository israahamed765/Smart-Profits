## What ran

`npm run db:verify-operational` is a gated, **read-only** operator CLI:

- Refuses unless the write-freeze is engaged and the P14.17 removal marker is valid.
- Checks `schema_migrations` and that `001_current_schema.sql` is applied.
- Confirms `merchants`, `workspaces`, `track_events`, and `guard_decisions` exist.
- Records `COUNT(*)` before and after a freeze-mutation probe (must match).
- SELECT-smokes the four catalog tables.
- Reads through production repositories (`readAccounts`, `listWorkspaces`, `readEvents`, `listGuardDecisions`).
- Attempts product writes; they must fail with the freeze `503`.
- Confirms `data/` has no catalog JSON and none is recreated.
- Confirms `nac-demo.json` is present and the P14.17 archive is unchanged.
- Audits catalog repositories for JSON fallback / archive paths.
- Does **not** `INSERT`/`UPDATE`/`DELETE`, migrate, backfill, reconcile, cut over, or unfreeze.

Isolated tests (`tests/p14.19-postgres-only-operational.test.ts`) use a mocked `pg.Pool` and `SMARTPROFIT_TEST_PG=1` with a fake URL so they cannot touch live catalogs. They cover repository and HTTP smoke plus freeze rejection.
