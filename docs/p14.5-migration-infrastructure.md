# P14.5 — Migration infrastructure

**Date:** 2026-08-26  
**Scope:** Add a real PostgreSQL migration runner and lock the current schema as **001**. Dual-write JSON + PostgreSQL, APIs, Auth, Guard, and the Financial Engine are unchanged. No backfill. PostgreSQL is not primary.

---

## How to run

Explicit / deployment-time only:

```bash
npm run db:migrate
```

Requires `DATABASE_URL`. Does **not** run from Next, BFF, HTTP handlers, `queryPostgres`, or `npm run backend`.

---

## Layout

```text
server/db/migrate.ts              runner (library)
server/db/migrate-cli.ts          CLI process
server/db/migrations/
  001_current_schema.sql          current product schema
```

There is no `database/` folder (P14.1 still forbids that path). History lives in PostgreSQL table `schema_migrations` (runner bootstrap, not a product entity).

## Runner contract

1. Files `NNN_name.sql` in deterministic numeric order.
2. Migration id = filename.
3. `schema_migrations(id PK, applied_at)`.
4. Applied ids are skipped (second run idempotent).
5. Each migration runs in `BEGIN` … `COMMIT`. Failure → `ROLLBACK` and the id is **not** inserted.
6. The runner uses `pool.connect()` / `client.query`, **not** `queryPostgres` (which swallows errors).

---

## Request-path change (schema bootstrap only)

`queryPostgres` no longer calls `ensureGuardSchema` / `CREATE TABLE IF NOT EXISTS` on every query.

Unchanged (P14.4):

- `null` when `DATABASE_URL` is empty or during 30s backoff
- repositories dual-write order
- JSON fallback
- Vercel throw paths

If tables are missing because `db:migrate` was never run, the driver error is still swallowed → JSON fallback.

---

## DO NOT

- Run migrations from `/api/*` or Frontend
- Treat 001 as a backfill
- Make PostgreSQL primary in this phase
- Add FKs / new indexes “for later”
