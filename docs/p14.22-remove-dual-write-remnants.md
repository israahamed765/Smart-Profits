# P14.22 — Remove Legacy Dual-Write / JSON Catalog Fallback

**Date:** 2026-08-28  
**Scope:** P14.20 and P14.21 are GO. PostgreSQL is the only catalog store. This slice removes leftover dual-write / JSON-fallback machinery from the **product path**: `mergeEvents` (unused in production) and `assertProductWrite` on the four catalog repositories. It does **not** delete `.p14.17-json-archive/`, does **not** delete `nac-demo.json`, and does **not** start P14.23.

```text
P14.20 final cutover                 GO, freeze lifted
   ↓
P14.21 post-cutover verification     GO
   ↓
P14.22 remove dual-write remnants    ← this document
   ↓
P14.23 JSON archive cleanup          (later slice)
```

## Search before delete

Production JSON-store importers after this slice:

| Module | Uses JSON store? | Why |
| --- | --- | --- |
| `user.repository.ts` | **no** (already gone in P14.18) | PostgreSQL `merchants` only |
| `workspace.repository.ts` | **no** | PostgreSQL `workspaces` only |
| `event.repository.ts` | **no** | PostgreSQL `track_events` only |
| `guard-log.repository.ts` | **no** | PostgreSQL `guard_decisions` only |
| `demo.repository.ts` | **yes, on purpose** | `nac-demo.json` is not a catalog table |

`queryPostgres → JSON fallback` and on-read backfill were already absent from the four catalogs (P14.18). Confirmed still absent.

`mergeEvents` callers before this slice: only `tests/p14.18-postgres-only-storage.test.ts` and `tests/p14.4-repository-dual-write.test.ts`. Production HTTP uses `appendEvent` via `track.service.ts` only. **Removed from the repository.**

`assertProductWrite` on the product path was a transition freeze. P14.20 lifted that freeze. Catalog writes now go to PostgreSQL even if an operator re-engages the flag. The helper stays on `server/write-freeze.ts` for operator CLIs.

## Event identity (unchanged)

| Kind | `track_events.id` | Who writes it |
| --- | --- | --- |
| Backfilled / historical rows | SHA-256 hex (`eventDeterministicId`) | P14.9–P14.11 copier only |

The JSON payload still has no `id`. Existing SHA-256 keys are **not** migrated.
